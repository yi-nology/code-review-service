# AGENTS.md — guidance for ZCode agents working in this repo

This is the `review-service` codebase. Read this before editing; it captures facts
that are not obvious from the directory layout. The canonical, longer reference is
`docs/CODE_REVIEW_POLICY.md` — follow its gates and severity rules when changing code.

## What this service is

A code-review gateway. It receives PR/MR events (webhook or API), clones via the
go-git-platform, runs **Open Code Review (OCR)** as a subprocess with a multi-agent
workflow, computes a quality-gate verdict, writes findings back as inline comments
and commit status, and exposes a Vue.js web console. Supports GitHub, GitLab, Gitea,
GitCode, Tencent Code. Stack: Go 1.26 + Hertz + uber/fx + GORM/PostgreSQL.

## Common commands

Go (run from repo root):

```sh
make build            # go build -o bin/review-service .
make run              # go run .  (uses etc/config-local.yaml, listens on :8081)
make test             # go test ./...
make test-race        # race detector
make fmt              # gofmt tracked Go files
make lint             # go vet ./...
make lint-strict      # + golangci-lint (advisory; historical baseline not fully clean)
make vuln             # govulncheck
make check            # quality gate = test + lint + frontend-lint + frontend-build
```

Frontend (from `frontend/`):

```sh
npm install
npm run dev           # Vite on :3000, proxies /api → :8081
npm run typecheck     # vue-tsc (build runs this first)
npm run lint          # eslint . --quiet
npm run build         # typecheck + vite build
```

Integration test (`api_integration_test.go`) requires a running service:
`TEST_BASE_URL=http://localhost:8081 TEST_TOKEN=dev-token go test -v -run TestAPI -timeout 300s ./api_integration_test.go`.

Repo-integration tests (e.g. `internal/repository/postgres`) spin up Postgres via
**testcontainers**; those tests need Docker available.

## Architecture & layer rules (important for edits)

Layered, wired with `uber/fx`:

- `idl/*.thrift` → (thriftgo) → `biz/model/*` and `biz/router/*` and `biz/handler/*`.
  **`biz/model/*` is generated** (`// Code generated by thriftgo. DO NOT EDIT.`).
  To change a request/response shape, edit the IDL and regenerate with thriftgo —
  do not hand-edit generated files. `biz/handler/*` is partly hand-written on top
  of generated scaffolding; check whether a file is generated before editing.
- Handlers (`biz/handler/*`) → call service interfaces declared in `internal/app/`
  and `internal/service/*`. Handlers should stay thin.
- `internal/service/*` business logic. Within review: `internal/service/review/domain/`
  holds the pure domain types/interfaces (`Request`, `Response`, `Result`, `Finding`,
  runner/OCR aliases); keep it free of infra imports.
- `internal/repository/*` GORM data access behind interfaces; postgres impl under
  `internal/repository/postgres/`. GORM models are distinct from domain types —
  mapping lives in `internal/repository/postgres/mapping.go`.
- `internal/ocr/` is the **single entry point for all OCR capability** (runner,
  scanner, preview, 7 managers, LLM provider/adapter, config merge). See
  `docs/OCR_CORE_DESIGN.md`. `BuildConfig` is the one config-merge implementation
  (overrides > settings > fallback > defaults); route config changes through it,
  do not build a parallel merge path. The unified exec entry is
  `internal/ocr/internal/command.go` `Run` (three-stage SIGTERM → KillGrace → SIGKILL).
- `internal/modules/*` fx wiring (`fx.Provide` / `fx.Invoke`). New services must be
  registered here, mirroring the existing module pattern.

Sensitive areas (per `docs/CODE_REVIEW_POLICY.md`) require security-focused review:
provider/vcs clone & URL/SHA validation, webhook signature verification, OCR command
execution & env vars, writeback flows, and anything touching tokens/secrets.

## Conventions

- **Logging:** use `github.com/oekit/logx`, NOT stdlib
  `log`, `logrus`, or `zap` directly. `init.go` already wraps `logx.Default()` with
  a redacting logger that masks `Bearer`/`api_key`/`sk-`/`ghp_` etc. — rely on it and
  do not print raw secrets. Hertz uses `hlog`.
- **IDs:** use `github.com/oklog/ulid/v2` for new identifiers.
- **Config:** infra/deploy tuning only via env vars + `etc/config-{env}.yaml`
  (`local`/`dev`/`prod`, selected via `--env`). Business config (Git tokens, OCR
  engine, project policies, rules) lives in the DB and is managed from the web
  console / settings API — do not add env vars for business settings. `DATABASE_URL`
  and `REVIEW_TOKEN` are required to run.
- **Migrations:** schema changes go through GORM AutoMigrate (on by default).
  `migrations/*.sql` are optional/manual and already covered by AutoMigrate;
  `deploy/migrations/` are one-off manual cleanup scripts for existing deployments.
- **go.mod:** has local `replace` directives for `ekit` (default `../ekit`) and the
  go-git-platform (default `../go-git-platform`) used by
  `make setup-local-deps`; paths may be overridden with `EKIT_PATH` / `GIT_SDK_PATH`.
  `github.com/apache/thrift` is pinned to v0.13.0 — do not bump (codegen contract).
- **Platform backends:** `main.go` blank-imports
  `github.com/yi-nology/go-git-platform/backends/all` to register all git platform
  providers (v0.32.0+ no longer auto-registers). Adding a new backend means ensuring
  this import covers it.
- **Frontend:** Vue 3 + Element Plus + Pinia + vue-router, TypeScript, `@` alias →
  `frontend/src`. API layer (`frontend/src/api/`) and types (`frontend/src/types/`)
  must stay in sync with backend thrift models. Component/UI work should match the
  existing tab/wizard patterns (see `frontend/src/components/model-settings/`).

## Before you finish

- Run the gate for the area you touched: backend → `make test lint fmt`;
  frontend → `npm run lint --prefix frontend && npm run build --prefix frontend`.
- New/changed externally reachable endpoints need auth, validation, and failure-path
  tests (per policy).
- Don't commit generated `biz/model` changes without the corresponding IDL change.
- Mask secrets in logs and avoid building OCR/shell/git args from unchecked input.
